# ClauseCatcher spike test harness

Offline, $0 test inputs + runner for the AssemblyAI API spikes (voice_agent, two_path).

## Files

- `FORMAT.md` — verified audio format requirements (cites AssemblyAI docs URLs).
- `make_audio.py` — generates test WAVs with Windows SAPI (built into Windows 11, no install, no network).
- `audio/` — generated WAVs + their exact `.txt` scripts:
  - `rep_pitch.wav` / `.txt` — 4-line rep pitch (correct / contradiction / contradiction / ambiguous claims).
  - `monitor_question.wav` / `.txt` — the ClauseCatcher wake question.
  - `rep_then_question.wav` — rep line 1 + 2s silence + monitor question, for single-session tests.
- `resample_audio.py` — resamples `audio/*.wav` to 24 kHz into `audio_24k/` via FFmpeg (offline, $0). See "Two-step Q2 probe" below.
- `audio_24k/` — 24 kHz mono 16-bit copies of the same 3 WAVs (+ `.txt` files), same names as `audio/`.
- `fake_contract.json` — 4 clauses (3.1, 4.2, 5.3, 6.1) with `section_number` + `literal_text`.
- `fake_contract.pdf` — same contract rendered as a PDF (via the already-installed `pymupdf`).
- `run_spikes.py` — runner: checks the API key, runs the other spikes, enforces a budget cap, prints a PASS/FAIL table.

## Setup (one-time)

Set the AssemblyAI API key as a persistent env var, then open a **new** shell (setx does not affect the current one):

```
setx ASSEMBLYAI_API_KEY <your key>
```

## Commands

```bash
# 1. Regenerate the test audio (idempotent, offline, $0)
python make_audio.py

# 2. Run the spikes + get the PASS/FAIL table
python run_spikes.py
```

`run_spikes.py` exits:
- `2` if `ASSEMBLYAI_API_KEY` is unset (checked before any network call).
- `1` if any check is FAIL/NO DATA, or the budget cap is exceeded.
- `0` if everything passed.

## Cost

`make_audio.py` and offline checks: **$0**, no network. `run_spikes.py` only spends money once it invokes the real spike scripts against the AssemblyAI API; it aborts remaining spikes once cumulative `est_cost_usd` (self-reported by each spike in its `out/*.json`) exceeds **$1.00** total.

## Two-step Q2 probe

Live run 2026-09-13 hit `internal_error` on Q2/Q3; AssemblyAI's docs neither
confirm nor rule out 16 kHz input as the cause (see
`../protocol/PROTOCOL.md`, "Live-run doc check"). This is a cheap two-step
isolation: step 1 repeats Q2 exactly as before (16 kHz, `audio/`) to confirm
it's still reproducible; step 2 reruns the identical test against a genuine
24 kHz WAV (`audio_24k/`, generated by `resample_audio.py`) — the only
variable that changes.

```bash
python resample_audio.py   # one-time: builds audio_24k/ from audio/ via ffmpeg

# step 1: identical config retry at 16kHz
python run_spikes.py --spike voice_agent --spike-args "--only Q2 --audio-dir audio"

# step 2: same test, genuine 24kHz WAV
python run_spikes.py --spike voice_agent --spike-args "--only Q2 --audio-dir audio_24k"
```

`--only` and `--audio-dir` are voice_agent spike flags owned by that spike's
agent — confirm the exact flag names/values in `../voice_agent/spike_voice_agent.py`
before running if they've since changed. `--spike-args` is shlex-split and
passed through verbatim to the selected spike's argv; `run_spikes.py` prints
the exact command it launches. Add `--dry-run` to see the derived
timeout/cost and exact command without spending anything or needing the API
key (e.g. `python run_spikes.py --dry-run --spike voice_agent --spike-args "--only Q2 --audio-dir audio_24k"`).

## Result file contract for spike scripts

Each spike script (`../voice_agent/spike_voice_agent.py`, `../two_path/spike_two_path.py`) should write its results to its own `out/*.json`, as a single object or list of objects shaped like:

```json
{"id": "Q1", "pass": true, "est_cost_usd": 0.02, "detail": "free-form note"}
```

Expected `id`s: `Q1` (proactive speech), `Q2` (single-session silence), `Q3` (client-side tool call), `T1` (keyterm WER), `T2` (claim-check latency).
